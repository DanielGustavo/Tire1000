# Frontend do zero a partir do Figma

## Destination

O frontend (`frontend/`) reconstruído do zero a partir do design no Figma (arquivo "Tire-Mil", fileKey `gNZUfCRJ0aiHIkcy5sugtE`) — mobile-first primeiro, depois um passe de adaptação para desktop. Um design system extraído do Figma (tokens Tailwind de cor/tipografia + componentes base: Button, Field, Select, IconButton, Bullet) é a fundação sobre a qual toda tela é construída.

A informação de arquitetura (IA) segue o Figma, não as rotas atuais:
- Uma **Landing Page pública** nova, com **Sign in**/**Sign up** como modais sobre ela — substitui as rotas de página inteira `login.tsx`/`signup.tsx`.
- A **Homepage** passa a incluir a lista paginada de "Suas redações" (com os estados de processando/rejeitada/avaliada) — absorve o que hoje é `essay-history.tsx`, que deixa de ser uma rota separada.
- A compra de créditos vira o fluxo **price modal + redirect Stripe**, sem página avulsa — `credits.tsx` deixa de ser uma rota separada.
- `themes.tsx`, `theme-detail.tsx`, `essay-upload.tsx` (fluxo de câmera/upload) e `essay-result.tsx` (Correção) continuam existindo como telas próprias, reconstruídas visualmente.

Destino alcançado quando as 6 telas/fluxos abaixo estiverem implementadas batendo com o Figma, em mobile e em desktop:
1. Landing + autenticação (Sign in/Sign up modais)
2. Homepage (Temas em destaque + Suas redações paginado)
3. Listagem de temas (+ filtro)
4. Detalhe do tema (+ variante sem crédito)
5. Envio de redação (fluxo de câmera no mobile, fluxo de upload de arquivo no desktop — ambos entram por um modal de dicas)
6. Correção — resultado da Revisão/Avaliação (+ estados in-progress/loading)

## Notes

- **Exceção às normas padrão do Wayfinder**: este mapa carrega execução, não só decisão — cada ticket entrega a tela construída em código (mergeada em `frontend/`), não um documento de decisão. O usuário quer o frontend pronto ao final do mapa.
- Arquivo Figma: fileKey `gNZUfCRJ0aiHIkcy5sugtE` ("Tire-Mil"). Nós de referência: Design System `5:3`, Assets `5:1268`, Components `33:2`, Responsive/mobile `5:1551`, Desktop `106:1830`.
- Sempre carregar a skill `figma-design-to-code` antes de chamar `get_design_context`.
- Sempre invocar `/grilling` e `/domain-modeling` quando a resolução de uma ticket envolver decisão de comportamento/estado, não só estilo puro.
- Vocabulário do domínio em `CONTEXT.md` (Correção, Revisão, Avaliação, Eixo, Destaque). Contrato de API e casos de uso já implementados: `.scratch/tire1000-mvp/spec.md`.
- Convenção de teste deste repo (`CLAUDE.md`): testes vivem na camada de application; UI pura normalmente não pede teste dedicado — não criar teste de componente só porque existe uma tela nova, a menos que haja lógica não-trivial.
- `get_metadata` nos nós `5:1551` (mobile) e `106:1830` (desktop) sozinhos estoura o limite de tokens da ferramenta — ao abrir uma ticket, peça `get_metadata`/`get_design_context` só do nó da seção/tela específica, não do canvas inteiro.

## Decisions so far

- **[01-design-system](issues/01-design-system.md)**: design system implementado em `frontend/src/index.css` (tokens `@theme`: cor, sombra "hard" 2px, tipografia título/default/small) + `frontend/src/components/{Button,Field,Select,IconButton,Bullet}.tsx`. Peso de fonte via utilitário Tailwind (`font-bold`), não bakeado no token de tamanho. Ícones via `lucide-react` (novo devDep — os nomes de camada do Figma batem 1:1 com o pacote). Bullet confirmado **não-circular** por screenshot real do Figma, apesar do nome sugerir círculo — implementado com cantos retos. Fonte Lato via Google Fonts `<link>` em `index.html`.
- **[02-landing-e-autenticacao](issues/02-landing-e-autenticacao.md)**: `frontend/src/pages/landing.tsx` + `frontend/src/components/Modal.tsx` (novo componente de design system) + roteamento em `App.tsx`. `/` alterna entre `LandingPage`/`HomePage` conforme `getAccessToken()`; `/login`/`/signup` são rotas compartilháveis que abrem a LP com o modal correspondente já aberto (redirecionam pra `/` se já autenticado); fechar qualquer modal (backdrop/Esc) navega pra `/`. Cadastro é wizard de 2 passos: dados da conta → seleção de créditos (`creditsQty` só é enviado no `POST /auth/signup` depois que o usuário escolhe uma quantidade ou clica "Continuar sem comprar créditos agora" — a ADR-0005 citada na ticket foi substituída pela ADR-0009, checkout no signup é opt-in). Preço em R$ não é exibido nos botões de crédito (só existe no Stripe, ADR-0002) — só quantidade, igual `credits.tsx`. Login social (Google) do Figma não implementado, fora de escopo do MVP. Tokens novos: `--text-hero`, `--text-subtitle`, `--color-neutral-600`, `--color-alert-100`, `--color-error-100`; variantes novas em `Bullet` (`alert`/`error`/`info`/`pink`, os 2 últimos com hex cru por não serem estilo nomeado no Figma).
- **[03-homepage-e-historico](issues/03-homepage-e-historico.md)**: `frontend/src/pages/home.tsx` reescrito, absorve e deleta `essay-history.tsx` (rota `/essays` removida). Ícone de notas do header = **saldo de créditos** (não "Suas redações" como a ticket cogitava), único entry point do price modal (`components/PriceModal.tsx`, novo) — confirmado com o usuário. Paginação de "Suas redações" é client-side (`GET /essays` não pagina, fora de escopo do backend). `EssayDTO`/`toEssayDTO` ganhou `finalScore: number | null` (mudança aditiva no backend, confirmada com o usuário — Figma mostra a nota no card, o DTO da lista não tinha o campo). Classificação visual por status segue `RESENDABLE_STATUSES` (promovida de `essay-result.tsx` pra `essay-service.ts` junto com `REJECTION_REASON_LABELS`) em vez do agrupamento solto da ticket — `EVALUATION_FAILED` não é reenviável (ADR-0001). Componente novo `components/TexturedCard.tsx` (card com textura de pontos, reaproveitado em temas e redações — assets em `frontend/src/assets/card-texture{,-dark}.png`). `Bullet` ganhou `size?: "fixed"|"auto"` + variante `"white"`; `IconButton` ganhou `rotate?: "left"|"right"` (mesmo padrão do `Bullet`). Tokens novos: `--color-neutral-{20,200,500}`.
- **[04-listagem-de-temas](issues/04-listagem-de-temas.md)**: `frontend/src/pages/themes/themes.tsx` reescrito (migrado pra pasta por página; `theme-detail.tsx` continua flat, fora de escopo desta ticket). Filtro por eixo é **só o modal** (`ThemesFilterModal`) — confirmado via `get_design_context` do frame "Temas" (106:2006): não há chips de eixo inline na listagem, só busca + ícone que abre o modal. O modal do Figma mostra um Select single-value **e** uma "Tags List" com 3 chips removíveis simultâneos — mismatch com o backend, que só aceita um `topicId` singular em `GET /themes` (`list-themes.ts`/`theme-repository.ts`, sem suporte a multi-eixo). Decisão (usuário, via `/grilling`): implementar **só o Select** (com uma opção síntética "Todos os eixos" pra limpar o filtro) — a Tags List do Figma foi descartada, não é multi-seleção real, é dado de exemplo do componente genérico reusado. "Filtrar"/"Voltar" no modal são apply/cancel (estado pendente só aplica em "Filtrar"). Paginação client-side (`GET /themes` não pagina, mesmo padrão da ticket 03) — `EssaysPagination` promovida pra `components/Pagination.tsx` (nome genérico, sem dependência de Essay) já que agora tem 2 consumidoras. `IconButton` ganhou `size?: "default"|"large"` (mesmo padrão de `Bullet`/`rotate`) pro botão de filtro 48px do search bar.

- **[05-detalhe-do-tema](issues/05-detalhe-do-tema.md)**: `frontend/src/pages/themes/theme-detail.tsx` reescrito (migrado pra pasta por página, mesmo padrão de `home/`/`themes/`), substitui `theme-detail.tsx` flat. Frame "Tema" com/sem crédito do Figma são visualmente a mesma tela — a diferença é só destino do CTA: `handleStartEssay` navega pra `/essays/new?themeId=` se `userQuery.data.credits > 0`, senão abre `PriceModal` (mesmo componente da ticket 03). As duas variantes de botão do Figma ("Tirar foto"/"Fazer upload") ficam lado a lado sempre, ambas disparando o mesmo `handleStartEssay` — o ponto de entrada real do fluxo de câmera/upload (modal de dicas) é escopo da ticket 06, aqui só o CTA. Token novo `--text-subtitle-small` (20px/bold, estilo "subtitle small" do Figma, usado no título de cada Texto motivador). **Gap de backend fechado nesta ticket** (via `/grilling` com o usuário, decisão registrada — imagem de Texto motivador não tinha nenhum jeito de virar URL, `fileKey` chegava cru na API): novo bucket S3 privado `ThemeAssetsBucket` + distribuição CloudFront com Origin Access Control (`backend/sls/resources/theme-assets.yml`), env var `THEME_ASSETS_CDN_DOMAIN`; `toReferenceTextDTO` agora recebe `themeAssetsBaseUrl` e devolve `content.url` pronta pra `<img src>` em vez do `fileKey` cru (frontend nunca soube de bucket/CDN). Só a plumbing de código entra agora — deploy real da infra e upload do asset do seed (`seed/mapa-comunidades.png`) ficam como passo manual do usuário, documentado em `backend/README.md` (seção "Seeding themes/topics"); até lá a imagem do Texto motivador II aparece quebrada em produção/dev (confirmado via captura de tela nesta sessão, esperado). Lógica de dados/estado extraída pra `useThemeDetailPage.ts` (mesmo padrão de `useThemesPage.ts`); badges de ENEM/eixo promovidos pra `components/ThemeBadges.tsx` (2º consumidor, reaproveitado por `ThemeListItem`) — ambos ajustes do `/code-review` desta ticket. CTA fica desabilitado enquanto `currentUser` carrega, pra não mandar erroneamente pro price modal um usuário com crédito (`credits` só cai pra `?? 0` depois que a query resolve).

## Out of scope

- Breakpoint de tablet dedicado — só mobile e desktop; o meio-termo fica por herança natural do CSS responsivo.
- Mudanças de lógica de negócio/casos de uso do backend — este mapa é só frontend visual e estrutural sobre as APIs já existentes (ver `.scratch/tire1000-mvp/spec.md`).
- Login social (Google) — já fora de escopo do MVP (ver spec do backend).
- Paginação/rate limiting de API — contrato de backend já definido; o frontend só consome o que existe.
